# audio_filter

ComfyUI 音频处理节点。目前包含一个节点。

## Audio Harshness Suppressor

> **状态：实验性，效果尚未调好。** 目前没有找到可靠的调参办法——判别量在真实素材上
> 分不开「刺耳段」与「正常人声」（见下文「一个已知的失效模式」），所以默认参数取的是
> **不把事情弄坏**的一组，而不是**能解决问题**的一组。请把它当作一个方向尚存、实现
> 未成熟的尝试，而不是一个即插即用的去刺耳工具。

> **Status: experimental, not tuned to a satisfactory result.** There is no reliable
> tuning procedure yet — the decision value cannot separate genuinely harsh material
> from ordinary vocals on real audio (see the known failure mode below), so the
> defaults are chosen to *avoid damage*, not to *solve the problem*. Treat this as a
> promising direction with an immature implementation rather than a drop-in de-harsher.

针对音频里扎耳朵的高频——齿音嘶声、镲片飞溅、过亮的"存在感"。

**它不是静态 EQ。** 固定高架衰减会把整条轨道变闷；这个节点逐帧测量目标频段，
只在它真正突出来的那些瞬间把它压下去。在合成的元音 + 周期性 /s/ 信号上实测：
默认参数把齿音压低 **11.8 dB**，而齿音之间的元音段只变化 **0.93 dB**。

### 检测原理

每个 STFT 帧（2048 点 Hann，hop 512）比较目标频段的能量密度与全谱能量密度：

```
tilt_dB = 10*log10(频段密度 / 全谱密度)
```

频谱平坦的信号测得 0 dB，高频自然滚降的信号测得负值。因为是比值，
该数值与输入音量无关，所以 `sensitivity_db` 不需要为每个文件重新标定。

超出 `sensitivity_db` 的部分**线性**映射成 0..1 的驱动量（每多超出 1 dB 就多拿
满衰减的 1/1.5），再用非对称一阶滤波器平滑（上升走 attack，下降走 release），
最后只作为增益曲线乘在频段内的 bin 上。所有声道共用同一条曲线，立体声像不会移动。

频段外的 bin 完全不碰；频段内在非刺耳的帧上增益恒为 1。

### 参数

| 输入 | 默认 | 说明 |
| --- | --- | --- |
| `harsh_low_hz` | 2500 | 关注频段下沿。2500 Hz 覆盖存在感与齿音 |
| `harsh_high_hz` | 9000 | 关注频段上沿。刺耳感偏最高频时可提到 14000 |
| `sensitivity_db` | -6.0 | 频段要比全谱密多少 dB 才动手。平坦信号为 0 dB，越小越激进 |
| `max_reduction_db` | 18.0 | 最刺耳处的最深衰减。设 0 即完全不处理 |
| `attack_ms` | 5.0 | 衰减淡入速度。保持短，才能抓住刺耳的起始 |
| `release_ms` | 120.0 | 衰减淡出速度。太短会听出抽吸感（pumping） |
| `mix` | 1.0 | 干湿比，用来 A/B 对比 |

### 调参建议

- 刺耳感听起来偏最高频（嘶嘶声）→ `harsh_high_hz` 提到 14000，`harsh_low_hz` 提到 5500
- 觉得压得不够 → 先把 `max_reduction_db` 从默认 18 再往上提，或把频段收窄到真正刺耳的那一段，再考虑动 `sensitivity_db`
- 觉得正常内容被压暗 → `sensitivity_db` 提到 -3，或收窄频段
- 听到呼吸/抽吸感 → `release_ms` 提到 250
- 拿不准就先设 `mix=0.5` 对比，再决定

### 默认值是怎么定的

**默认值取的是"不会把事情弄坏"的一组，不是"效果最强"的一组。**

在一段真实的 32 kHz 生成音乐上，把默认调到看上去最对症的一组
（频段 5500–14000、阈值 -12、上限 18 dB）后实测各片段的副作用：

| 片段 | 5500–14000 / -12 / 18 | 2500–9000 / -6 / 12 |
| --- | --- | --- |
| 0–6 s | -1.75 dB | -1.31 dB |
| **6–9 s（男声）** | **-17.69 dB** | -2.03 dB |
| 9–12.8 s | -9.46 dB | -2.19 dB |
| 12.85–13.45 s（听者指认的刺耳段） | -16.20 dB | -2.27 dB |
| 13.5–15 s | -2.56 dB | -1.56 dB |

第一组**把男声压得比刺耳段还多**。原因见下节。默认因此退回第二组的**频段与阈值**
（2500–9000 / -6）。上限后来从该组的 12 提到了现在的 18，但这张表量的是
**频段 + 阈值 + 上限三者同时改动**的联合副作用，单独把上限从 12 提到 18 并未重新实测过，
所以上表读作「频段与阈值的选择才是主要风险来源」，不要读成「18 这个上限被否掉了」。

### 一个已知的失效模式（重要）

**当刺耳感不是"某个频段整体偏多"，而是"某段素材的频谱结构异常"时，本节点无法把它与
正常内容区分开。** 这是实测出来的，不是推测：

同一素材上，逐段的 6–14 kHz 频段倾斜（本节点的判别量）：

| 片段 | 倾斜 p90 | 倾斜 max |
| --- | --- | --- |
| **6–9 s（男声，听者认为不刺耳）** | **-1.08** | **+2.23** |
| 12.85–13.45 s（听者指认刺耳） | -7.59 | -5.49 |

**判别量认为男声比那段刺耳素材"更刺耳"。** 因此在该频段内不存在任何阈值能只压刺耳段
而不压男声——实测：阈值高到保住男声时（-3 dB），刺耳段衰减为 -0.01 dB。

进一步用听者反馈定位后，那段刺耳的听感特征（把 6 kHz 以上整段低通后大部分消失、
但残留一层"粗粒感"）与测到的非谐波谱峰（频率为基频的 13.71 / 15.46 / 16.45 倍）
一致，指向**非线性伪影**（混叠、量化或模型生成痕迹）：不是某个频段能量偏多，
而是能量出现在错误的、非谐波的位置。**减法 EQ 与动态处理都无法修复这类问题**，
把高频整段切掉也会留下那层粗粒感。

这类伪影如果来自采样环节——例如在 44.1/48 kHz 生成后重采样到 32 kHz、
或下游解码器没做抗混叠——**只能在采样环节修掉**。一旦能量已经折叠进带内，
任何后处理都补不回来。

### 走过的弯路（留档，避免重犯）

- **用缓入曲线换"自然"**：smoothstep 让刚过阈值的帧衰减接近 0，
  真实素材整段平均只衰减 1.27 dB，听不出任何变化。
- **用降阈值换力度**：把阈值从 -6 降到 -12 后，目标素材只多压 0.6 dB，
  正常唱音却多掉 8.1 dB——动态处理器退化成静态 EQ。
- **用谱平坦度（噪声性）做门控**：目标素材与正常唱音的平坦度分布基本重叠
  （p50 0.040 vs 0.034），完全不成立。
- **用逐带局部包络（谱峰）检测**：驱动比 1.0x，完全没有选择性，
  因为唱音的谐波峰相对谐波间谷底同样是"凸起"。
- **靠基频轨迹定位刺耳时刻**：自相关追踪器在快速上滑处饱和，
  给出的时间窗是错的；最后是靠听者的秒数反馈 + 谱质心才定位准确。
- **光加宽频段**：频段上限从 9 kHz 提到 14 kHz 后目标段衰减仍是 0.00 dB。
  频段宽度与阈值是耦合的，必须一起改。

检测量本身在四种候选（频段/全谱倾斜、频段/带外密度、频带电平对自身慢平均、
倾斜对自身慢平均）中比过：时域参考方案分离度只有 2.3 dB，被排除；
频段/带外密度判别力与所选方案等价，但取值无界，阈值跨素材更不稳定，因此未采用。

### 已知边界

- **不能区分"频段整体偏多"与"频谱结构异常"**，见上节。
- **非线性伪影（混叠、量化、模型生成痕迹）不在能力范围内。**
- 爆音/咔哒/电流声属于瞬态问题，不在范围内。
- 窄带纯音（例如单独一个 6.5 kHz 正弦与低频能量相当）不会被处理。
- 低频刺痛（鼻音、轰隆）不在范围内。

## 安装

放进 `ComfyUI/custom_nodes/` 后重启 ComfyUI。无额外依赖，只用已经装好的 PyTorch。

## 测试

核心算法 `dsp.py` 不依赖 ComfyUI，可以脱离服务端直接跑：

```
python tests/test_dsp.py
```

覆盖：形状/dtype 保持、刺耳段被压而其余部分不动、频段选择、声道联动、
0 衰减透明、0 干湿比直通、静音、极短片段（1 采样）、退化频段、
attack/release 时间常数、批内独立、偏暖素材不被过度处理、
抽吸气被深压而唱音不动，以及耗时（60 秒立体声约 0.13 秒）。
